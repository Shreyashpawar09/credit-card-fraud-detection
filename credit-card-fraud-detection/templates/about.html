About & Methodology

Problem Statement

Credit card fraud causes significant financial loss, and fraudulent transactions are extremely rare relative to legitimate ones. This project explores supervised machine learning approaches to flag potentially fraudulent transactions from anonymized, PCA-transformed transaction features, as a final-year academic exercise.

Dataset

The reference dataset is the public Kaggle "Credit Card Fraud Detection" dataset, containing transactions made by European cardholders in September 2013. Features V1–V28 are the result of a PCA transformation applied by the dataset's original authors to protect confidentiality; only Time and Amount are not transformed. The target column Class is 1 for fraud and 0 for legitimate transactions. Fraud accounts for roughly 0.17% of transactions in the real dataset — a severe class imbalance.

Preprocessing

  • Exact duplicate rows are removed before splitting, to avoid the same transaction appearing in both the training and test sets.
  • Rows with missing, non-numeric, or infinite values in required columns are dropped.
  • Data is split into stratified train / validation / held-out test sets using a fixed random seed. The test set is touched only once, for final evaluation.
  • Scaling (for Logistic Regression) and any class-imbalance resampling are fit on the training split only, never on validation or test data.

Algorithms Compared

  • Logistic Regression (baseline) — a linear model with standardized features and balanced class weights.
  • Random Forest (comparison model) — an ensemble of decision trees, which does not require feature scaling, also using balanced class weights.
  • Logistic Regression + SMOTE (when imbalanced-learn is installed) — synthetic minority oversampling applied strictly within the training fold.

The final model is selected by validation Average Precision (area under the Precision-Recall curve), not accuracy, because accuracy is misleading when fraud is such a small fraction of all transactions.

Evaluation Metrics

Precision, Recall, F1-score, ROC-AUC, Average Precision (PR-AUC), and the full confusion matrix are reported on the held-out test split. The decision threshold is tuned on validation data only (maximizing F1) and then applied, unchanged, to the test split.

Limitations

  • This is an educational prototype, not a production payment-security system. No PCI DSS or regulatory compliance is claimed.
  • Model scores are raw outputs, not calibrated real-world probabilities, unless explicitly calibrated and labeled as such.
  • A random stratified split may let "future" transactions leak into training relative to a real deployment, where the model only ever sees past data. A chronological split (available in src/preprocessing.py) better approximates deployment conditions but was not necessarily used for the metrics shown, depending on how training was run.
  • Synthetic-data results (when present) demonstrate the software only and must never be cited as real fraud-detection performance.

Security & Privacy

  • No real card numbers, CVVs, expiry dates, or cardholder names are collected anywhere in this application.
  • Uploaded CSV files are processed in temporary storage and deleted immediately after analysis.
  • Only derived prediction outputs (not raw feature vectors) are stored in the demonstration history database.
